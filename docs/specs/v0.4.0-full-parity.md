# AvtoHmver 0.4.0 full parity and release

## Problem Statement

AvtoHmver has working pieces of the requested 0.4.0 experience, but users still encounter inconsistent Pause behavior, incomplete remote video playback, gaps in Discover and native workflows, an unfinished managed P-HAR runtime, and an Android upgrade that could hide saved phone data. The parity ledger still marks 36 included areas Partial. Publishing 0.4.0 now would promise a complete experience that has not passed the required edition, device, package, and release checks.

## Solution

Finish every included parity area across Host, native Viewer, Server, and Android Viewer+. Give all playback modes one reliable Pause state; make previews and Discover continuous and informative; complete branding, motion, position tagging, package staging, and the remaining management workflows. Preserve on-device Viewer+ data through the Android origin change. Verify remote browsing and video on a real iPhone through both Tailnet IP and MagicDNS, plus native Viewer behavior. Run the full release checks on the final commit, then version, tag, push, verify artifacts, and publish 0.4.0.

## Implementation Decisions

- The parity ledger is the release authority. Every included area must reach acceptance across its applicable editions; the shorter beta checklist is an interim checkpoint.
- Host, native Viewer, Server, and Android Viewer+ are distinct product clients. Extend parity applicability to Viewer+ rather than treating it as the native Viewer.
- Playback uses one shared paused state. Automatic timers and media-end advancement are suspended while paused; explicit Next remains available; Resume restores only prior running activity. Interruptions bypass motion effects.
- Thumbnail storage includes source identity and change detection. A failed preview displays a labeled fallback in native and browser grids.
- Discover appends near the scroll end, preserves list state, reports known counts and byte totals, and says Unknown where providers omit data. Provider search support follows verified interfaces, with named exceptions and direct-URL fallback.
- Motion affects navigation and state changes, not the media content. It respects reduced-motion preferences and never delays Pause, panic hide, error display, or teardown. New installs keep the System theme; saved themes persist.
- P-HAR begins with the official RGB video model and all required position labels. Fetch official release assets on demand, record exact source identity, size, and measured SHA-256, and reject mismatches. Do not bundle checkpoints or acceptance media. Support a measured CPU fallback. A successful native inference probe is required in addition to fixture tests for two adjacent windows and human overrides.
- Managed P-HAR setup remains opt-in with durable status, bounded cancellation, repair, and a self-test. Model downloads must not become trusted merely because a URL is official; the recorded bytes must match.
- The Android Viewer+ upgrade migrates old on-device data before changing the local web origin. Stage and verify data, restore it transactionally, and keep compatibility mode with Retry if migration fails or is interrupted. A pack export does not cover all on-device data.
- Remote acceptance requires a real iPhone using direct Tailnet IP and MagicDNS, browser video and images, native Viewer access, Host tray survival, server-side permission denials, identity revalidation, and clean shutdown. Diagnose the observed Safari failure from actual request and response behavior before choosing a code fix.
- Same-PC linked staging removes only its managed stage when an original changes or moves. A portable exported `.chpack` is independent and remains compatible with the original importer.
- The final release operation is ordered: complete acceptance, update version and notes, commit, tag and push `v0.4.0`, verify GitHub artifacts, then publish.

## Testing Decisions

- Test user-visible behavior at the highest practical seam: one disposable sample library exercised through installed Host, Server, native Viewer, browser, and iPhone. Use focused lower-level tests only where the end-to-end fixture cannot isolate a failure.
- Reuse existing playback clock, stream range, package round-trip, P-HAR provenance, browser smoke, Android emulator, edition permission, and installer lifecycle test patterns. Add new seams only where no existing boundary exposes the behavior.
- Exercise Pause at every queue boundary: media end, clip end, image dwell, review timeout, GOON phase, late play request, mode change, Next while paused, and teardown. Verify no skip and no unwanted Resume.
- Exercise thumbnail creation, cache reuse, source change and replacement, missing file, generation failure, and labeled fallback for openable images and videos.
- Exercise Discover near-end loading, duplicate/failed provider pages, selection and scroll preservation, counts and cumulative sizes, Unknown values, provider exceptions, and direct-URL fallback.
- Exercise motion with rapid interruption and reduced-motion enabled; assert critical controls and errors remain immediate.
- Exercise actual P-HAR inference on locally held labeled clips and neutral controls, plus two-window threshold, nonfinite scores, rescan stability, and human overrides. Measure CPU and GPU behavior rather than claiming compatibility from package installation alone.
- Exercise Android migration as a same-signature upgrade with local files, large blobs, snapshots, settings, and session pins. Interrupt at each phase, simulate insufficient space, verify Retry and hashes, and assert old data remains usable until complete.
- Exercise `.chpack` portable round trips in the original game, linked-stage invalidation after move/change/replacement, cancellation, preservation of originals, and no deletion of independent exported copies.
- Exercise Server and Viewer permissions at the HTTP boundary, installed edition startup and shutdown, occupied port and lock behavior, Host tray continuity, Tailnet identity changes, and real iPhone playback through both address forms.
- On the final commit, run formatting, locked workspace checks and tests, strict Clippy, browser and Android checks, Windows installed-edition review, installer upgrade/uninstall data preservation, and artifact inspection. Linux desktop manual verification is waived; automated Linux build checks remain in scope.

## Out of Scope

- Slideshow, the Cock Hero player mode, and VR.
- Changing the new-install default to Tactical. The optional Tactical palette and saved choices remain supported.
- Manual Linux desktop acceptance, as waived by the user. Automated Linux build validation remains included.
- Treating the original game's importer as a new AvtoHmver playback mode.
- Bundling P-HAR model weights or private acceptance media into the release.
- Replacing P-HAR with an image classifier whose labels merge required positions.

## Further Notes

- The product remains at version 0.3.4. The parity ledger still has 36 Partial areas; no 0.4.0 tag or release exists.
- A real iPhone 18 reached a disposable Server by direct Tailnet IP and displayed images. Safari video failed in preview and at the direct ID stream, including after substituting a baseline H.264/AAC fast-start clip. MagicDNS did not load. The exact Safari request and response exchange is still unknown.
- Fresh Android Viewer+ installation rendered remote thumbnails after its local origin changed from HTTPS to HTTP. Existing on-device data needs migration before an upgrade can ship.
- P-HAR tag policy has fixture coverage, while the managed runtime is currently a stub. Official model files lack published digests; repository-pinned measured hashes and real inference are required by the agreed plan.
- A disposable diagnostic showed that HTML placed in the served library can execute under the Host origin. Close that active-content route before release; the diagnostic Host is stopped while the user has paused the iPhone test.
