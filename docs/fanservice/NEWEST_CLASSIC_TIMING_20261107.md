## What the inspected newest instructions establish

- `BuildBeatQueue` at `0x14831c630` starts target time at the travel duration, sets fire time to target minus travel, and advances target time by each interval. Pattern multipliers and the speed parameter are native floats; interval and travel are doubles. The interval is the maximum of the configured minimum and `abs(float multiplier) * base interval * (1 / float speed)`. Negative multipliers occupy queue time without counting toward the requested stroke total. Zero counts as a stroke.
- `RebuildQueueFromCurrentState` at `0x1483200e0` retains fired entries, starts future fire time at the current master timeline plus 0.1 seconds, retains pattern position and applies the same float-speed division. Future target time adds the stored travel duration.
- Newest `FBeatEvent` array stride is 0x48 bytes; the older native queue evidence used 0x28 bytes. The original six timing fields retain their offsets. Newer fields must not be inferred from the older layout.
- `OnBeatReachedCenter` at `0x14831f730` broadcasts the center-hit delegate and increments completion. Its Classic completion gate requires the assigned count, all queued entries fired and no outstanding spawned beats. Music-mode completion is handled separately. The additional native time-to-next-beat and timing-error fields are outside the shared queue precision fix.

The JavaScript queue and future rebuild previously divided by the full JavaScript speed number. Both now round speed to `Math.fround` before arithmetic, matching the inspected native parameter. Values that overflow or underflow native float representation fail without changing an active queue. Six independently generated arithmetic cases cover decimal speeds 0.9, 1.1 and 0.1, float pattern values, rests, zero multipliers and the minimum interval. They are explicitly marked analyst-derived static fixtures in [newest-classic-timing.json](../../tests/fixtures/fanservice/newest-classic-timing.json).
