## Observed executable paths

- `CheckAndPlayObjectiveTick` has five expressions and `ScriptBytecodeSize=91`. Statement 0 compares `Session Objective` with `GameInstance.CurrentSessionObjective` using `EqualEqual_ByteByte`; statement 1 jumps past statement 2 if false; statement 2 calls `PlayObjectiveTickAnim`. This is a matching-objective UI animation gate, not Timer completion.
- `InitializeRoundObjectiveAndStats` statements 11–12 compare the selected round objective enum with `1`; when it matches, statements 26–27 copy `RoundManager.GetCurrentState().SelectedOption.ObjectiveParam` to `GameInstance.Objective_TimeRequired_Seconds`, then statement 28 jumps to the function exit. This establishes a per-round Timer target assignment, not its allowed range.
- `InitializeOriginalSessionObjectiveCounts` statement 4 copies `GameInstance.Objective_TimeRequired_Seconds` into `Original Objective Time Required Seconds`. In `ExecuteUbergraph_BP_GlobalManager`, statements 1269 and 1282 add the original value to the current target, and statement 1283 stores the sum back to `GameInstance.Objective_TimeRequired_Seconds`; this is a separate adjustment path, whose entry/guard was not resolved in this bounded pass.
- In `ExecuteUbergraph_BP_GlobalManager` statements 2367–2380, statement 2367 tests `GameInstance.CurrentSessionObjective == 1`; statement 2368 branches away if false. Timer branch statements 2369–2372 divide `PlayerVariablesStruct.SessionLength` by `GameInstance.Objective_TimeRequired_Seconds` and pass that ratio to `UIManager.ManuallyUpdateObjectiveProgressBar`. Statements 2373–2374 branch on `PlayerVariablesStruct.IsAllowedToCum?` and `PlayerVariablesStruct.HasCame?`; statements 2376–2377 format session length and update the UI Timer display. Statement 2378 computes `SessionLength >= Objective_TimeRequired_Seconds` with `GreaterEqual_IntInt`. Statement 2379 is `EX_PopExecutionFlowIfNot` on that result: false pops the current execution-flow target, while true continues to statement 2380, an `EX_Jump` to bytecode offset **92333**.
- The validated offset map resolves **92333** to statement **2330**, `IsModifierActive?("SuccuFrenzy")` (the prior note's tentative `SetSessionDuration` target was wrong). On an ordinary card, when that modifier is inactive, statement 2331 jumps to 2357. Statements 2357–2362 test whether the current card is type 5, 6, or 3; if none, statement 2362 jumps to 2334. If `HasCumMeterOverideTriggered?` is false, statement 2334 falls through to 2336. The **mode/round discriminator** is `GameInstance.IsCumRound?` at statement 2336: true falls through to statements 2337–2339, which mark the override triggered, spawn the 100% cum-meter override, and start the cum-window timer; false jumps to statement 2354 `RoundWinOverride`. Its wrapper dispatches to Ubergraph entry **79488** (statement 1947), which jumps to statement 1367 (offset **56800**): the shared victory path creates and adds the victory widget (1367–1368), updates the objective title (1369), calls `UpdateMetric` with metric id 14 and increment 1 (1370; enum label not recovered), creates a notification (1372), pauses the beat sequence (1379), and schedules a delay (1380). Thus Timer threshold reaches a concrete **round-win** producer when `IsCumRound?` is false, and a **cum-window** producer when true. This remains static control flow, not a runtime acceptance result.
- Mode setup explains the split. In Ubergraph startup statements 611–612, `GameModeSelection == 0` jumps to statement 657, which writes `GameInstance.IsCumRound? = true`, then statement 658 joins the initial draw. `GameModeSelection == 1` instead follows statements 613–614 to 654, bypassing that write. `InitializeRoundObjectiveAndStats` (used for round setup) separately sets `IsCumRound?` from `RoundManager.GetCurrentState().CurrentRound >= TotalRounds` at statements 5–7. `InitializeCumRoundState` statements 0–2 compute the same condition. This supports Classic mode 0 using the cum-window branch and an ordinary Tower round using `RoundWinOverride`; the exact call site for each round initializer and the cum-window duration were not traced here.
- Reproducible resolver and complete local map: `.test-tmp/resolve_timer_offsets.py` and `.test-tmp/timer-current-offset-map.json`; the [compact durable target map](timer-current-bytecode-map-20261109.json) records all 299 resolved direct targets and source SHA-256. The corrected map totals the export's declared **99,921** bytecode bytes; all **299** direct jump/push targets align to statement boundaries. The seven `EX_UnicodeStringConst` values in this decoded asset each required an asset-local four-byte correction from the generic UAssetAPI `Visit` size estimate; without it the map overcounted by 28 bytes and only 120 of 297 jump targets aligned. This is an empirically validated offset calibration for this asset, not a general claim about the codec.
- `SetSessionDuration` statements 5–7 increment `PlayerVariablesStruct.SessionLength` by one and store it. Its statements 0–4 first check modifier/card conditions; the timer setup/call schedule and whether every wall-clock second contributes require a wider trace.

## Parity boundary

`static/fanservice/objectives.js` uses a 300-second default and a 10,800-second maximum. This asset trace supports an integer Timer target, a per-round objective parameter, progress `SessionLength / target`, an inclusive `>=` threshold, and the guarded Classic cum-window / ordinary Tower round-win split. It does **not** establish the default, selection UI limits, complete elapsed-time accounting, cum-window duration, reward amount, or physical gameplay behavior. The older generic `Analysis/widget-functions` tree must not be represented as this selected installed asset.
