## Confirmed newer Edge rules

- [`AdjustPostEdgeBreakDelay.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/AdjustPostEdgeBreakDelay.json), blob `6bb6107fcf3654491bc1980ceac2666cc45d8436`, computes `PostEdgeBreakDuration + FTrunc(EdgeStreak / 5)` and clamps to 1–8. The newer Ubergraph initializes `PostEdgeBreakDuration` to 1.75. This agrees with the fixed-base model in `edge.js`.
- [`CountdownEdgeHold.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/CountdownEdgeHold.json), blob `331a3ea673ed997fe3d35663a72f247ead564027`, dispatches to `ExecuteUbergraph_BP_EdgeManager` entry 10358. The newer graph sets a looping one-second timer, decrements `CurrentEdgeHoldDuration` by one per callback, and clears the timer at zero. This agrees with the one-second first tick and subsequent tick model.
- [`CalculateEdgeReward.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/CalculateEdgeReward.json), blob `0b287a8518eb66712be4bfebf42559be66ba5885`, calculates normal rewards as `10 + 5 * (EdgeStreak + 1)` and perfect rewards as `35 + 15 * (EdgeStreak + 1)`.
- [`ExecuteUbergraph_BP_EdgeManager.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/ExecuteUbergraph_BP_EdgeManager.json), blob `7e16f3551a6d0718a53871911d344523f97a3075`, shows both repeat branches call `CalculateEdgeReward`, pass its output to `AddToEdgeBank`, then increment `EdgeStreak`. The formula therefore uses the prior streak. The first streak initialization is a separate path and adds no repeat reward.
- [`AddToEdgeBank.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_GlobalManager/AddToEdgeBank.json), blob `ad5b2aac6c4af51c26573bf9c0ad9b74c2fbacea`, adds `Coins` directly to `EdgeBank`.
- The pinned wrappers [`TriggerEdge.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/TriggerEdge.json) and [`TriggerEdgeV2.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/TriggerEdgeV2.json) dispatch to Ubergraph entries 1404 and 9014. The hold callback dispatches to entry 10358.
- [`AdjustBreakDuration.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/AdjustBreakDuration.json), blob `dae077eb23205a5bec2c7f5c92b38d97e3439c45`, applies a random reduction from 0.05 to 0.1 and clamps the result to 1–30. [`CheckEdgesUntilMercy.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/functions/BP_EdgeManager/CheckEdgesUntilMercy.json), blob `ad8d30314bc53b1de4c7a9adc1da5cbef4eefdc6`, opens Mercy at `CurrentEdgesUntilNextMercy <= 1`.

The selected graph also routes normal and perfect meter changes through separate `EdgeCumMeterAdd` and `PerfectEdgeCumMeterAdd` properties. The pinned [`blueprint-class-defaults.json`](https://github.com/xxjuggernaut9113xx-design/reJOIce/blob/1a18e9a8ccd97fbfb0cc785f6f3d2e025ad86cff/Analysis/ReferenceBuilds/newer-20261017/blueprint-class-defaults.json), blob `4d8d626ce87aed1a6896e1e82e069e66c99dfc95`, contains those property declarations but no numeric defaults, so this evidence does not establish the newer build’s meter amounts. `CalculateEdgeReward` returns reward points only. The same metadata lists `PerfectEdgeStreakThreshold` but gives no default value; the implementation’s `.85` perfect threshold remains v0.04-derived rather than verified against this newer build. The implementation retains its existing meter values pending numeric default/runtime evidence.
