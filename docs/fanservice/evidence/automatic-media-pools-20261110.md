# Automatic ordinary media pools

`static/fanservice/media_selection.js` uses the recovered heat-category boundaries (0–30, above 30 through 70, above 70 through 100) to choose a heat-modifier column, then performs native weighted event selection. The player no longer displays, stores or reads a user-selected speed pool. Ordinary card completion, next-media actions and post-Mercy draws invoke automatic selection; scripted music, active encounters, Edge and release transitions retain explicit control.

The native asset evidence is `.test-tmp/current-BP_DrawManager-functions.json` (`DetermineCardV2`, `ChooseWeightedEventFromArray`, `TriggerSelectedEvent`) and `.test-tmp/current-BP_GlobalManager-cdo.json` (`AdjustHeatLevelWeights`, `AdjustComboLevelWeights`, and their `Update...Weights` functions). Native heat categories and combo tiers adjust each eligible event's BaseWeight in that order, clamping after each addition to 0â€“100. `ChooseWeightedEventFromArray` draws from 0 through the total event weight and selects the first event whose cumulative weight is strictly greater than the draw.

`static/fanservice/data/special-events.json` contains all 12 rows decoded from the installed game's `/Game/NewSetup/DataTables/SpecialEventDataTable`, including the speed, Succubus, and frenzy events. Its source hashes are embedded in the file. The table was extracted with retoc and decoded through UAssetAPI with a scratch mapping updated from the current `SpecialEventDataStruct` export's ordered properties. `weightedEvents` applies the recovered weight adjustments to caller-provided eligible rows. The caller remains responsible for native eligibility, scripted music, edge, release, and encounter transitions. The earlier deterministic threshold-only choice has been removed from the player. `heatBand` identifies a modifier column; it is not the selected media event.

`BP_GlobalManager.CheckEventConditions&ReturnArray` appends eligible events in this order: slow, medium, fast, temptation, Succubus, mercy, ass frenzy, boob frenzy, store, favorite frenzy. The three speed check functions contain only Return and EndOfScript, with no coded guard. Ass and boob frenzy require Brain Melter enabled and the high heat category (enum 0). The Succubus check includes its separate spawn, shield, modifier, and cooldown conditions. The table row named `NewRow` has event code 12; `BP_DrawManager.TriggerSelectedEvent` routes code 12 to `FavoriteFrenzyEvent`. The decoded table's `isEligible` and cooldown fields are defaults, not a substitute for these checks. `weightedEvents` expects the caller to pass supported eligible rows in native candidate order.


## Shared-player integration and scope

The player supplies supported media events in native candidate order: slow, medium, fast, eligible Succubus, and high-heat ass/boob frenzy when the pre-session body-part frenzy setting is enabled. Available frozen media membership is also required. Forced Succufrenzy, Slow and Steady, and Double Time modifier overrides retain their existing explicit dispatch rules. The Succubus gate applies Demon Proof, exorcist cooldown, heat/combo requirements and toggled Shield/Enhanced Plating effects before the weighted draw. The selected event and shield state are checkpointed with the session.

The full table also contains non-media minigames and further special-event dispatch. Those handlers are outside this integration and remain open under #51; selection here is the native weighted distribution conditional on the supported eligible media events. This does not claim that the entire original event dispatcher is finished.

`fanservice_auto_media_smoke.cjs` passes in WebKit: public Start and natural card completion change ordinary pools without a selector or gameplay-counter injection. It uses fixture-authored short pacing and a deterministic seed, not a native pattern-fidelity claim. Weight clamp order, cumulative strict-greater selection, category boundaries and zero-weight behavior have focused unit tests.
