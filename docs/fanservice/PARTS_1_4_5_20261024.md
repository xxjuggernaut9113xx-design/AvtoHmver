# Parts 1, 4 and 5 — implementation checkpoint, 2026-10-24

Scope follows the user's request to prioritize Server/shared foundation,
music/offline/synchronization, and mobile. This does not declare all three complete.

## Completed changes

- Profile sync binds each request to the original Server, library/profile,
  connection identity/key, revision and local profile contents. Stale responses
  are rejected after a profile, connection or local-edit change.
- Only one sync request can be in flight per transport. GET review rechecks its
  binding before applying the remote profile. PUT accepts only the expected next
  revision. Conflicts and timeouts leave the local revision untouched.
- Sync and ordinary Server JSON request timeouts cover the response body as well
  as headers. An ambiguous PUT timeout tells the user to inspect remote revision
  before retrying. No automatic overwrite or revision advancement occurs.
- Snapshot downloads reject empty, oversized and incomplete payloads in both
  streamed and Blob fallback paths. Content-Length comparison accounts for
  HTTP content encoding. Cross-library manifests are rejected before download.
- Failed replacement and quota failures retain the previous snapshot. Downloads
  have a bounded request/body deadline. Existing durable session pins remain.
- A synchronous failure during a multi-file IndexedDB write now explicitly aborts
  the transaction. A quota failure on the second imported file cannot commit the
  first file while reporting that nothing was saved.
- PWA shell v13 includes the new sync module. Android 0.3.9/versionCode 309 uses
  the same shared frontend; build and runtime evidence are recorded below.
- The fixture runner supports a focused list of checks and an explicit prebuilt
  test executable. CI still compiles from locked source by default. The fixture
  creates a temporary synthetic library; it does not open a user library.
