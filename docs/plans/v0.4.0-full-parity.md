# v0.4.0 full parity plan

## Release boundary

Complete every included area in [the parity ledger](../parity/STATUS.md) for Host, native Viewer, Server, and Android Viewer+. Keep Slideshow, the Cock Hero player mode, and VR excluded. The Linux desktop manual check and a new-install Tactical default are waived. Existing theme choices remain intact. The shorter [beta checklist](../release-beta-gate.md) is an interim checkpoint, not the 0.4.0 release gate.

## Work order

1. **Repair remote video and address resolution.** Capture the actual iPhone Safari request method, Range header, response status, and transferred byte count without recording media names or device addresses. Reproduce the direct-stream and browser-preview failures with the disposable fixture, then fix the confirmed cause. Verify direct Tailnet IP and MagicDNS on iPhone 18, image and video playback, native Viewer access, permission denials, Host tray survival, and Host shutdown.
2. **Make P-HAR usable.** Fetch the official RGB checkpoint from its fixed release identity, record its size and SHA-256, and reject later mismatches. Build and probe a managed native dependency stack, including a measured CPU fallback. Run at least seven-second clips through actual inference; verify the required labels, two adjacent windows at confidence 0.70 or higher, rescans, and human additions/removals. Use a local classifier acceptance set with known labels and neutral controls; keep its media outside the repository.
3. **Migrate Android Viewer+ data.** Start an upgrade on the old origin, stage local profiles, settings, files, snapshots, and pins in bounded chunks, verify integrity, then restore on the new origin. On interruption or insufficient space, keep the old data available in compatibility mode and offer Retry. Test a same-signature upgrade, large blobs, interruption, retry, and no partial restore. Recheck remote thumbnails and video in the upgraded app.
4. **Close the remaining ledger rows.** Add Viewer+ applicability to the ledger, then complete the native UI, playback, Discover, package, music, storage, classifier, maintenance, and edition workflows recorded as Partial. For each row, add focused automated checks and manual evidence in every applicable edition; update the ledger only after acceptance. Preserve the portable `.chpack` path and validate managed linked-package invalidation separately.
5. **Run final release validation.** On the final commit, run formatting, locked workspace checks and tests, strict Clippy, browser and Android checks, Windows installed-edition review, permission and lifecycle tests, `.chpack` round trip in the original game, and the real tailnet check. Verify GitHub artifacts and installer upgrade/uninstall data preservation. Then update version and release notes, commit, tag and push `v0.4.0`, verify artifacts, and publish the release.

## Current evidence and open risks

- The iPhone 18 reached a disposable Server library by direct Tailnet IP and displayed images. Safari video failed in both preview and the direct ID stream, including with a baseline H.264/AAC fast-start fixture. MagicDNS failed. The actual iPhone request and response exchange has not been captured.
- The Android origin change made remote thumbnails render in a fresh emulator install. Existing on-device Viewer+ data needs migration before an upgrade ships; emulator video playback and a real phone upgrade remain unverified.
- P-HAR position-tag policy and human override fixtures pass, but the managed installer is still a stub and has no native inference evidence. Official release assets have no publisher digests, so the approved repository pins must be measured and recorded from the official files.
- The last checked main artifact workflow passed; validation must be repeated at the final release commit. The worktree contains uncommitted earlier evidence updates that must be reviewed before staging.
