# P-02 — Controls

2026-10-27 isolated Windows Host acceptance: the marked fixture launched with
the installed libmpv DLL and rendered a three-video native Player queue. After
Pause, explicit queue selection loaded a video at 0/4 seconds and held that
position for five seconds while the control read Resume. The Right shortcut
advanced queued items while the shared pause stayed active, and Resume began
the selected item from its start rather than skipping it. Grid previews for
images and videos rendered; a deliberately broken video showed the explicit
"Preview unavailable" fallback. This checks the development Host fixture,
not the installed Host or every queue boundary.

Native Feed follow-up on the same fixture: after skipping a missing image and
the deliberate broken-video error, Feed reached a valid video. Pause held
Parity video 2.mp4 at 2.133333/4 seconds for five seconds. "Next ready item"
selected Parity video 1.mp4 at 0/4 seconds while the control still read
Resume. Review inherited the pause state; its fixture queue was empty at that
point. Review now exposes a visible
Pause/Resume control alongside its decision controls.

Populated native Review follow-up: two images in the marked disposable fixture
were marked as needing review. Starting Review displayed the first image. The
shared Space shortcut held that image for twelve seconds, beyond its ten-second
countdown, and resuming advanced the displayed image. The running fixture Host
predated the new visible Review Pause/Resume button, so that button itself
still needs a direct UI check on an updated build.

Native GOON follow-up: starting a 60-second isolated session with shared
pause already active showed Paused and 00:00 active for five seconds. Resume
advanced the session clock and phase. Pausing later at 00:47 active held the
same phase, BPM, task, and 00:47 time for another five seconds; ending the
isolated session completed it without consuming the paused interval.

2026-10-26 GOON browser follow-up: corrected the pre-start shared-pause button
to show Resume with pressed state before an audio clock exists. Starting while
paused held at 0:00 and the first beat; Resume started the session. Pausing a
running session subsequently held its elapsed time and phase. The regression
test also verifies that an unstarted session is not automatically started by
Pause/Resume unless Start had armed it. All 193 browser tests pass.

2026-10-26 browser acceptance: at the supported wide desktop breakpoint,
Portrait Wall rendered three generated images. Pause held the same three
sources beyond their ordinary dwell interval. Changing from the paused Wall
to Review retained Resume/pressed state and held the current review image;

same pause state as media controls. Starting a session while paused starts
and pauses it under the engine lock at the same monotonic timestamp; no

audio and native music freeze playback and track-end advancement, preserving
manual audio pauses. External/embedded connector acceptance remains separate.

shared by Player, Feed, Review, GOON, and Portrait Wall. It blocks EOF handling,
automatic candidate activation, review deadlines, wall deadlines, and GOON
driving. Resume shifts deadlines rather than restarting dwell, and resumes only
the Host session ID paused by this control. Explicit Next remains available.
New deadlines created while paused use the paused clock anchor. Panic restore
retains shared pause and avoids counting overlapping pauses twice. Regression
test: `shared_pause_preserves_deadlines_and_is_idempotent`. Browser-wide shared
pause and installed queue-boundary verification remain outstanding.
