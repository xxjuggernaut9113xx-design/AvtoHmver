# A-01 — Typed service boundary

Recorded: 2026-09-29. Migrated from the native workflow inventory; historical observations retain their original dates where stated.

Extract `library`, `settings`, `discovery`, `storage`, `downloads`, `jobs`, `backup`, `export`, `media`, and `playback` services; adapters retain every path, method and format. H/S full; V scoped. Library list queries, pages, validation, and admission use a typed transport-independent service directly from Host and through the unchanged Server `GET /api/media` adapter. Settings reads use a shared audience-aware service from Host and the `GET /api/settings` adapter, with direct/HTTP parity and remote path-denial tests. Storage accounting has typed categories, disk and source usage models shared by Host and the `GET /api/storage` adapter, with direct/HTTP parity and Viewer, shutdown, and maintenance tests. Discovery provider descriptors and catalog live in a typed service used directly by Host and through `GET /api/search/providers`. Backup inventory and validated download paths use a typed service shared by Host and Server admin adapters, with Viewer/shutdown denial and direct/HTTP parity tests. Maintenance job list, lookup and start use a typed service from Host and the existing Server admin adapters, with direct/HTTP parity and rejection tests. Source-list export and import now use shared services from Host and the existing Server adapters, retaining their payloads, duplicate handling and reminder update with direct/HTTP parity and Viewer/shutdown/maintenance admission tests. Native Host source creation and deletion use shared services behind Server `POST /api/sources` and `DELETE /api/sources/{id}`; deletion retains the `delete_files` query contract and has direct/HTTP, Viewer, shutdown and maintenance tests. Session admission, media byte-range planning, typed download activity, and global/per-source download controls also have direct/HTTP tests. Media rating, approval, guarded undo and bulk tag add now have direct Host service calls and Server adapters with direct/HTTP tests and boundary denials. Settings writes and discovery search are now typed services: `services::settings::apply_settings_patch` (typed `SettingsPatch` ops per field group; `PATCH /api/settings` is a thin adapter keeping its auth checks and payloads) and `services::discovery::search` (route-inline provider search moved out of `src/routes/search.rs`); download pause/resume/status are typed ops in `services::downloads` with typed request/response shapes replacing ad-hoc JSON. Each has unit tests; HTTP behavior is preserved. Server-side Viewer role authority now exists via `services::access::Caller` (Role::Host/Server/Viewer plus negotiated ViewerPermissions); service boundaries check capabilities, raw peer locality is only the resolution input, and media mutation handlers re-verify edit authority behind the middleware. Source edits also use `services::sources::patch` from Host and the existing Server PATCH adapter, with nullable retention, permission, and shutdown tests.
