2026-10-26: native Media & Storage now shows typed accounting categories,
free/total disk values with Unknown for missing data, source usage and quotas,
and retention rules. Refresh retains the chosen source by ID and clears a
removed selection. Local owners can permit one source sync, apply a configured
retention rule, clear thumbnails, and remove archives with the existing exact
confirmation phrases. Native actions share the HTTP handlers and admission
checks. Cleanup holds its maintenance lease for the actual blocking work;
source cleanup excludes a new source download while deleting eligible files.
No source retention rule means native cleanup is refused rather than treating
an unset policy as zero retained files. Viewer controls remain read-only.

2026-11-06: Server and native Host cleanup both apply the saved retention
rule. Requests with an omitted rule and no configured retention, or an
explicit zero, fail before removing originals. The browser disables cleanup
until a rule is saved and shows storage accounting failures with the server's
error message. Remote browser Settings and storage controls are read-only.
HTTP regressions exercise the rejection, successful configured cleanup, and
unavailable storage status.
