# D-02 — Viewer lifecycle

Recorded: 2026-09-29. Migrated from the native workflow inventory; historical observations retain their original dates where stated.

saved-host list/edit/remove, unknown-field-preserving migration, stable identity, negotiation, validated retries/reconnect/switching. Viewer native device preferences preserve unknown JSON fields through appearance/layout saves and default missing legacy fields. The native Viewer has a Switch Host action that returns to its saved-host picker, where the next connection is revalidated against Tailscale and instance identity. The Server handshake advertises a read-only Viewer permission set that the native client applies to commands and visible controls. After a network failure, Viewer retries read requests against its pinned Tailnet address only after the Host handshake reconfirms the same instance, protocol and permissions; writes are not retried. Automated tests cover identity replacement, permission change and missing identity rejection. Re-resolving a moved Host now sweeps the Tailnet peer inventory for the same library instance_id and reconnects at the new address, persisting the working endpoint; the connect dialog streams Progress/Attempt/Finished events with attempt count, last error and a manual Retry button instead of a silent spinner.
