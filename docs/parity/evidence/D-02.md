# D-02 — Viewer lifecycle

2026-10-28 headless Android Viewer+ probe: an isolated Android 35 emulator
installed the CI debug APK, reached the disposable Host fixture's Tailnet
address (`100.105.122.9:59386`), and listed fixture images and videos under
the matching library identity. The initial HTTPS localhost WebView blocked
HTTP Host thumbnail and video URLs as mixed content, despite successful API
fetches. Switching Capacitor's Android local origin to HTTP and rebuilding the
APK made valid remote thumbnails render at their expected 180-pixel width
(the deliberately broken fixture remained broken). The emulator terminated
while probing video playback, so streamed video is not confirmed. The emulator
needed a warm restart after first-boot WebView ANRs. This is an emulated client
on the same physical computer, so it does not establish native Viewer or
physical second-device acceptance.

Changing the Android WebView origin also changes its localStorage and IndexedDB
namespace. Existing Viewer+ installations using the HTTPS origin need a
verified data migration before an in-place mobile upgrade can be considered
safe; the current APK check used a fresh isolated emulator installation.
The Viewer+ grid now replaces a failed thumbnail with a labelled placeholder;
the isolated mobile browser smoke test verified that fallback with a missing
thumbnail URL.

Recorded: 2026-09-29. Migrated from the native workflow inventory; historical observations retain their original dates where stated.

saved-host list/edit/remove, unknown-field-preserving migration, stable identity, negotiation, validated retries/reconnect/switching. Viewer native device preferences preserve unknown JSON fields through appearance/layout saves and default missing legacy fields. The native Viewer has a Switch Host action that returns to its saved-host picker, where the next connection is revalidated against Tailscale and instance identity. The Server handshake advertises a read-only Viewer permission set that the native client applies to commands and visible controls. After a network failure, Viewer retries read requests against its pinned Tailnet address only after the Host handshake reconfirms the same instance, protocol and permissions; writes are not retried. Automated tests cover identity replacement, permission change and missing identity rejection. Re-resolving a moved Host now sweeps the Tailnet peer inventory for the same library instance_id and reconnects at the new address, persisting the working endpoint; the connect dialog streams Progress/Attempt/Finished events with attempt count, last error and a manual Retry button instead of a silent spinner.
