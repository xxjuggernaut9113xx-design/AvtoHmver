# M-04 — Import/export

2026-10-28 original-game bridge check: a previously exported phone-local
`.chpack` with no cover was rejected by the verified v0.04 bridge because its
manifest contained `"preview": ""`. Core and browser exporters now omit the
optional preview field when no cover is selected. The focused core manifest
test passed. A new archive produced by the browser writer from the same
synthetic image (1,109 bytes, SHA-256
`cf6966a8e46c367900e6e76ff8878d82dd9bfeb08511cbf648a90a0c4e36cb6e`)
passed the original-game bridge's build identity, archive, and media checks
and was staged into the isolated v0.04 game copy. On startup, the unmodified
game extracted its manifest and media file. A second cover-bearing Server
selection export (SHA-256
`0db59ec1bde3a251680a709dfb13115f955cf52f8ab93c2f317e23096ce7c56f`)
also passed the bridge and was extracted by the game with its preview and two
media files. Both checks used the isolated game/profile; both game processes
were stopped after extraction. This verifies original-game import/extraction
of portable AvtoHmver output. Unlock-screen display and gameplay of these
specific two archives were not observed.

The normal browser export smoke also passed with the new no-cover assertion
using installed Chrome in headless mode. Its `phone-local.chpack` (SHA-256
`bdf2c8efb5b63447280237508bbe6658a41f679c82c814c79315c400664102e3`)
passed the bridge, and the unmodified isolated v0.04 game extracted its
manifest and media after restart. The isolated process was stopped. This
confirms the user-facing browser export path as well as the writer API.

2026-10-26: Organization now exposes source-list import/export, portable
package export, and local-owner linked staging. These actions remain reachable
after the Explorer shell hides legacy sidebar controls. A regression test
invokes each transfer action and verifies its existing handler; remote browser
hosts do not receive the linked action. In an isolated Windows Server browser,
Organization → Stage linked .chpack → Stage library showed progress followed
by the completed local archive path. Live archive/source-move acceptance and
portable-copy preservation are recorded in V-02. External game import remains
unverified.

2026-10-01 portable export follow-up retains the temporary archive for the
response lifetime, holds maintenance admission while reading originals, and
cancels bounded reads on shutdown. It excludes unavailable and virtual media
that has not been rendered. Physical clips are typed as video. Package source
paths must resolve to files inside the library. Export writes accurate
image_count, video_count and total_media alongside the existing 0.02a media
entries, matching a read-only inspection of an existing CockHero V0.04 pack.
Format inspection and byte round trips do not constitute manual game import
acceptance.
